### 11.2 high — a release publishes an image nothing built or tested before the tag
- **Kind:** release, ci
- **Where:** `.github/workflows/release.yml:4-5,36-75` (trigger, no gate but `verify-version`), `.github/workflows/ci.yml:240-261` (`build` = `bun run build` only), `Dockerfile:49,112-114,139-151,226,229,246,274`
- **Defect:** (a) no CI job runs `docker build`; the Dockerfile's own assertions — bun digest/version match, `claude` binary staging, the >100 MB duplicate prune, `router-cli-owner` exit-64 probe, `tini --version`, `claude --version`, `claude-profile-check.js` in the pruned layout — execute for the first time on a `v*` tag, on both arches. (b) `release.yml` neither runs the suite nor checks that CI passed on the tagged commit or that the commit is on `main`.
- **Failure scenario:** (b) observed on v2.55.0 — main CI for `4b47af8` was created 10:55:24Z and finished 10:57:53Z; the release `build` jobs started 10:55:53Z, i.e. the tag was pushed ~30 s after merge and the image was built while `test` was still running (it happened to pass). A red `main` run, or a tag on an unmerged branch commit, publishes `X.Y.Z` + `latest` identically. (a) a merged PR that breaks any Dockerfile assertion (lockfile bump changing the SDK platform-package layout, base digest re-resolve, a `bin/build` output rename) is green on PR and `main`; it fails only after the version-bump PR is merged and the tag is pushed, leaving a tag with no image and a burned version number (`docs/RELEASING.md:205-211` forbids re-tagging).
- **Fix:** 1. `ci.yml`: add an `image` job — `docker/build-push-action` with `push: false`, `platforms: linux/amd64`, `load: true`, then `docker run --rm --entrypoint claude <img> --version`; run on every PR/push (≈70 s without cache export, see 11.3) or at minimum `paths:`-filtered to `Dockerfile`, `.dockerignore`, `bun.lock`, `bin/build*`, `native/**`, `packages/db/migrations/**`; add it to branch protection + `.dz/maintainer/maintainer.yml:39-45`. 2. `release.yml`: new first job `gate` that (i) `git merge-base --is-ancestor $GITHUB_SHA origin/main` and (ii) polls `gh api repos/{repo}/commits/$GITHUB_SHA/check-runs` until `lint`, `typecheck`, `test`, `build`, `ui-geometry`, `image` are `success` (bounded wait, fail on any other conclusion); `build` gets `needs: [gate]`. Needs `checks: read`. 3. `ci.yml:13`: `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` so a second merge cannot cancel the run the gate is waiting on. 4. `docs/RELEASING.md` §4-5.
- **Test:** extend `apps/api/test/integration/image-pins.test.ts` (it already parses both workflows): assert `release.yml` `build.needs` contains `gate` and that `ci.yml` has a job whose step uses `docker/build-push-action` with `push: false`.

### 11.3 medium — release buildx `gha` cache never hits and costs 123 s of a 191 s build
- **Kind:** perf, release
- **Where:** `.github/workflows/release.yml:103-106` (and the comments at `:26`, `:34-35`, `:63`)
- **Defect:** `cache-from/to: type=gha,scope=linux-<arch>` on a workflow that only ever runs on tag refs. Actions caches are readable from the creating ref and the default branch only; a cache written under `refs/tags/v2.54.2` is invisible to `refs/tags/v2.55.0`, and nothing on `main` writes these scopes (the `ci.yml` image job the comments cite was removed — `ci.yml:262-270`).
- **Failure scenario:** v2.55.0 amd64 log: `importing cache manifest from gha` then zero `CACHED` steps; `#45 exporting to GitHub Actions Cache … preparing 27.8s … sending cache export 95.0s … DONE 122.8s` out of a 191 s step (arm64 163 s, same shape). The image itself was pushed at +25.8 s. Each release also writes ~550 MiB of blobs per arch into the repo's 10 GB cache quota (visible in `gh cache list`), for nobody.
- **Fix:** delete `cache-to` from `release.yml:106`; keep `cache-from`. Let the 11.2 `image` job on `push: main` own `cache-to: type=gha,mode=max,scope=linux-amd64` (default-branch caches are readable from tag refs), optionally a second leg on `ubuntu-24.04-arm` for `scope=linux-arm64`. Rewrite the three stale comments. Expected: tag → published manifest drops from ~4 m 25 s to ~2 m 20 s cold, less when main's layers are warm.
- **Test:** none automatable offline; acceptance is the next release log showing `CACHED` on `bun install` and no `exporting to GitHub Actions Cache` step.
